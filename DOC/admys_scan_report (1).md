## 二、安全改进对比

### ✅ 已修复（4 项）

| # | 漏洞 | 旧状态 | 新状态 |
|---|------|--------|--------|
| 1 | `/api/notifications/latest` 未授权访问 | GET → **200** + 数据泄露 | GET → **401** 需要认证 |
| 2 | `/api/contact/send` 无验证码 | POST → 200 | POST → 400 + **Turnstile 验证码** |

| 4 | `/api/auth/register` 无密码策略 | 任意长度 | **10-128 位** + **3 次/窗口 → 429** |

### ✅ 新增安全机制（6 项）

| # | 机制 | 详情 |
|---|------|------|
| 1 | **HSTS** | `max-age=31536000; includeSubDomains` |
| 2 | **CSP** | `default-src 'self'; connect-src ... https://api.admys.cn https://challenges.cloudflare.com` |
| 3 | **Permissions-Policy** | `camera=(), microphone=(), geolocation=(), payment=()` |
| 4 | **Turnstile** | Cloudflare Turnstile 人机验证（联系表单 + 可能登录/注册） |
| 5 | **JWT 增强** | 新增 `iss`/`aud`/`jti`/`token_type`/`tokenVersion` 字段 |
| 6 | **全局 API 认证** | 新增端点全部返回 401（不再 403 由 WAF 拦截） |

### 📋 JWT 结构对比

```
旧: {sub, userId, role, iat, exp}
```

## 🟡 五、仍存在的问题

### 5.1 注册速率限制可被 Tor 绕过

**严重程度**：🟡 低危

虽然 3 次/窗口的速率限制已生效，但通过 Tor 网络每次请求可能走不同出口节点，Cloudflare 按 IP 限流的效果会被削弱。成功在限制触发前注册了 3 个账号。

**建议**：添加邮箱验证环节；考虑设备指纹限流（而非仅 IP）。

### 5.2 `/api/auth/me` 无速率限制

**严重程度**：🟡 低危

已认证状态下连续 15 次请求 `/api/auth/me` 全部返回 200，无速率限制。可能被用于：
- 用户枚举（通过 IDOR）
- 资源消耗

**建议**：对已认证端点也添加适度的速率限制（如 60 次/分钟）。

### 5.3 主站无速率限制

**严重程度**：🟡 低

连续 20 次请求主页无任何限制，可能被用作反射面。

### 5.4 JS Bundle 仍暴露 API 结构

**严重程度**：🟡 信息

新版 JS 中仍包含完整的 API 端点、认证逻辑和管理后台路由（新增 `/admin/users`）。
