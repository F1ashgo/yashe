# admys.cn 并发压力测试报告

**测试时间**：2026-07-19  
**测试方式**：Tor obfs4 网桥 → proxychains → Cloudflare → 源站  

> ⚠️ 所有请求经过 Tor 网络，实际并发上限受 Tor SOCKS5 代理瓶颈影响。以下数据反映的是 **经过 Tor 后的可达并发**，目标真实上限可能更高。

---

## 主站 (admys.cn) 并发测试

| 并发数 | 成功 | 超时 | 成功率 | 耗时 |
|--------|------|------|--------|------|
| 10 (×5轮) | 50/50 | 0 | **100%** | — |
| 50 | 50/50 | 0 | **100%** | 4s |
| 100 | 100/100 | 0 | **100%** | 7s |
| 200 | 191/200 | 9 | **95.5%** | 9s |
| 300 | 215/300 | 85 | **71.7%** | 13s |

### 结论
- **稳定上限**：~200 并发（经过 Tor）
- **开始衰减**：200+ 并发（~5% 超时）
- **严重衰减**：300 并发（~28% 超时）
- 超时根因推测：Tor SOCKS5 代理连接数/带宽瓶颈，非目标服务器限制

---

## API (api.admys.cn) 并发测试

| 并发数 | 正常响应 | 429限流 | 超时 | 耗时 |
|--------|----------|---------|------|------|
| 50 | 50 (401) | 0 | 0 | 6s |
| 100 | 100 (401) | 0 | 0 | 10s |

### 结论
- API 通用端点 **无速率限制**
- 仅 `/auth/login`（5次→429）和 `/auth/register`（3次→429）有限流
- 其他端点（如 `/notifications/latest`）可被高频调用

## 综合评估

| 指标 | 评估 |
|------|------|
| 主站并发上限 | 🟢 ≥200 (Tor 环境) / 推测直连 ≥500+ |
| API 速率限制 | 🟡 仅登录/注册端点，其余无限制 |
| Cloudflare 防护 | 🟢 100 并发内零损耗 |
| 超时成因 | 🟡 主要是 Tor 代理瓶颈，非目标问题 |

## 建议

1. **API 全局限流**：对 `/notifications/latest`、`/auth/me` 等端点添加速率限制
2. **直接压测**：如需真实上限，建议从非 Tor 环境直接压测
