# 雅舍网站安全、移动端与管理后台改造设计

## 1  背景

本次改造依据网站建设要求和 `admys_scan_report.md` 的扫描结果，同时结合代码审查修正报告中的误判。

需要同时满足：

- 保持现有黑、金、米白视觉风格和既有业务功能。
- 优化 8 个公开/会员页面及管理后台的手机端体验。
- 管理后台拆分为“通知推送”和“用户管理”两个页面。
- 修复公开接口滥用、通知越权、JWT 授权分散及输入校验不足。
- 移除当前版本中的敏感文件和凭据，建立后续阻断机制。
- 遵循分支提交、Pull Request 和 Conventional Commits 规范。

## 2  已确认决策

- 管理后台采用顶部双标签导航。
- “通知推送”沿用现有站内公告，不增加邮件、短信或浏览器 Web Push。
- 通知仅对已登录会员和管理员可见。
- Footer 删除电话和邮箱；联系页仍保留其联系方式。
- 小红书、抖音链接同步 Footer、侧栏和联系页。
- 注册采用 Cloudflare Turnstile + 服务端限流，不增加邮箱验证。
- 本次删除当前版本中的敏感内容并增加防护；不重写 Git 历史。
- 旧 `feat/admin-auth-hardening` worktree 和分支已删除，不复用其提交。

## 3  风险判断

### 3.1  确认需要修复

1. 注册、登录、联系表单缺少机器人验证和频率限制。
2. 联系表单服务端字段校验不足。
3. 公开通知接口暴露内部元数据，且与“会员通知”语义不符。
4. JWT 有效期过长、控制器分散解析 token、管理员权限依赖 token 内角色。
5. 仓库当前版本存在疑似 SSH 私钥、数据库/Redis/JWT 凭据和含个人信息的数据库转储。
6. 源站与测试端口防护缺乏可核验配置说明。
7. CORS 权限过宽，缺少统一的安全响应头策略。

### 3.2  不按扫描报告字面实施

- 当前使用 Bearer Token 且不依赖 Cookie，联系表单的主要问题不是 CSRF，而是匿名滥用。
- HS256 本身不是漏洞；高强度密钥、密钥轮换和可靠授权比盲目迁移 RS256 更优先。
- 前端分包不能隐藏 API，也不能替代后端鉴权；本次分包仅作为性能优化。
- Cloudflare 和 Spring Security 技术指纹不是有效安全边界，不做伪装式修复。

## 4  仓库敏感内容治理

### 4.1  当前版本

- 删除被跟踪的生产数据库转储。
- `.gitignore` 忽略 `sql/yashe_db_*.sql` 等运行时备份，但继续跟踪 `sql/init.sql`。
- 文档中删除私钥正文、数据库/Redis/JWT 明文和生产 IP，改为占位符与 Secret 配置说明。
- 运维脚本从权限受控环境文件读取数据库、Redis 和部署参数，不保存默认生产值。
- 将工作区外的扫描报告 JWT 替换为脱敏示例。

### 4.2  阻断机制

- 增加 Gitleaks 配置和独立安全扫描工作流，不修改现有部署工作流业务。
- 安全扫描阻止私钥、JWT、数据库密码和数据库转储进入新提交。
- README 明确禁止提交真实凭据、私钥、生产转储和个人数据。

### 4.3  必须人工完成的运维动作

代码不能自动替代以下动作：

1. 从服务器 `authorized_keys` 撤销已暴露部署公钥并生成新密钥。
2. 轮换 JWT、数据库和 Redis 凭据。
3. 更新 GitHub Secrets 与服务器环境文件。
4. 强制现有用户重新登录。
5. 安全组/防火墙关闭测试端口，并限制源站 Web 端口仅接受 Cloudflare/受信代理。

Git 历史重写不在本次范围内，后续需单独评估并通知所有协作者。

## 5  后端安全架构

### 5.1  集中认证与授权

新增 Spring Security JWT 过滤器：

1. 从 `Authorization: Bearer <token>` 读取 token。
2. 校验签名、过期时间、issuer、audience 和 token 类型。
3. 根据 `userId` 查询数据库。
4. 用户不存在、禁用或 token 版本失效时返回 401。
5. 使用数据库当前角色生成 Spring Security Authorities。

路由规则：

- 公开：注册、登录、联系表单。
- 已登录会员/管理员：`/api/auth/me`、评价、通知读取。
- 仅管理员：`/api/admin/**`。
- 其他接口默认拒绝。

控制器不再自行替换 Bearer 字符串或信任 JWT 内角色。

### 5.2  JWT

- 保留 HS256。
- `YASHE_JWT_SECRET` 为必填高强度环境变量，启动时校验长度。
- Access Token 默认 60 分钟。
- 增加 issuer、audience、`token_type=access` 和 `jti`。
- 本次不实现 Refresh Token；过期后重新登录。
- 轮换密钥后旧 token 全部失效。

### 5.3  Turnstile

注册和联系请求增加 `turnstileToken`：

- 前端使用 `VITE_TURNSTILE_SITE_KEY` 渲染控件。
- 后端使用 `YASHE_TURNSTILE_SECRET_KEY` 调用 Cloudflare `siteverify`。
- 生产环境缺失密钥时启动失败或请求失败关闭。
- 单元测试通过接口替身验证成功、失败、超时和重复 token。
- 本地开发使用 `.env.local` 和 Cloudflare 官方测试密钥，不将其写入生产配置。

### 5.4  限流

服务端对下列端点实行独立限流：

- 注册：每 IP 每分钟 3 次。
- 登录：每 IP 每分钟 5 次。
- 联系表单：每 IP 每分钟 3 次。

超限返回 HTTP 429、现有 `ApiResponse` 信封和 `Retry-After`。

应用限流使用受信代理处理后的客户端 IP；部署文档要求源站只接受受信代理流量。Cloudflare 侧同时配置边缘限流，应用限流作为第二层防护。

### 5.5  输入校验与错误处理

新增独立请求 DTO：

- 注册：姓名、邮箱、密码、电话、优惠码和 Turnstile token。
- 联系：姓名、邮箱、电话、主题、内容、预算和 Turnstile token。
- 通知：标题、正文、类型、状态。

规则：

- 字符串先 `trim`，邮箱统一小写。
- 密码长度 10～128。
- 所有文本有明确最大长度。
- 邮箱、电话、预算和通知类型采用格式或枚举校验。
- 不把数据库或内部异常消息直接返回客户端。
- 参数绑定、校验、限流和认证错误均保持 `{code, message, data}`。

### 5.6  会员通知

- `/api/notifications/latest` 改为需要会员或管理员认证。
- 只返回 `status=1` 的已发布通知。
- 公共响应 DTO 仅包含显示所需字段，不返回内部状态和更新时间。
- 会员登录、注册成功后立即刷新通知。

### 5.7  CORS 与安全头

- CORS 仅允许正式站点和显式本地开发来源。
- 仅允许实际使用的方法和 `Content-Type, Authorization` 请求头。
- Bearer 模式下 `allowCredentials=false`。
- API 增加 HSTS（由 HTTPS 边缘最终核验）、`nosniff`、frame 限制、Referrer-Policy 和 Permissions-Policy。
- 前端静态托管 `_headers` 增加适合当前资源的 CSP；不使用 `unsafe-eval`，仅为 Turnstile 放行 Cloudflare 官方脚本和 iframe 来源。

## 6  前端架构

### 6.1  路由与分包

- 使用 `React.lazy` 分割管理后台页面。
- 新增：
  - `/admin/notifications`
  - `/admin/users`
- `/admin/dashboard` 和 `/admin` 重定向到 `/admin/notifications`。
- 未知管理地址重定向到管理入口。
- 共用 `AdminLayout` 和 `RequireAdmin`。

### 6.2  后台顶部与导航

顶部左侧顺序：

```text
广州雅舍室内设计有限公司  管理后台
```

顶部双标签：

- 通知推送
- 用户管理

桌面端为横向标签；手机端保持两项等宽标签。返回网站、退出登录保持在右侧，窄屏时换到独立操作行。

### 6.3  通知推送页

保留现有功能：

- 创建通知。
- 查询通知。
- 发布/隐藏。
- 删除。

手机端：

- 表单单列。
- 每条通知使用卡片，不使用横向滚动表格。
- 操作按钮触控区域不小于 44px。

### 6.4  用户管理页

保留现有功能：

- 会员总数与今日新增。
- 邮箱搜索。
- 分页。
- 查看会员详情。

桌面端保留表格；手机端改为会员卡片，详情使用明确展开按钮并支持键盘操作。

## 7  公共页面改造

### 7.1  联系信息和社媒

- Footer 删除联系电话和邮箱。
- Footer 保留地址、二维码和“联络我们”标题。
- 联系页的电话、邮箱继续保留。
- 建立集中式社媒配置并同步 Footer、Sidebar 和 Contact：
  - 小红书：用户提供的完整主页链接。
  - 抖音：`https://v.douyin.com/k43Gt3WVPC0/`

### 7.2  手机端基线

- 最低宽度按 320px 设计。
- 320、360、390、430、768、820、1024px 均不得出现页面级横向滚动。
- 全局手机容器左右留白降为 16～20px。
- 导航在平板宽度前切换为手机菜单。
- 触控目标不小于 44×44px。
- 支持 `prefers-reduced-motion`。
- 焦点样式清晰，弹层可用 Escape 关闭并锁定背景滚动。

### 7.3  重点页面

- 首页：允许首屏文案换行，修复低高度/横屏布局；优化轮播媒体加载。
- About/Services/Expertise：压缩手机端间距，避免重复大标题和卡片拥挤。
- Projects：灯箱支持内部滚动、背景锁定、键盘和触控。
- Member：整理重复 CSS 覆盖，表单、通知和评价在 320px 可用。
- Contact：手机端减小大间距和卡片内边距。
- AdminLogin：增加手机断点和安全区域留白。

视觉继续使用现有品牌色、字体和动效，不进行全站视觉重构。
